## 交互与实现

选中主视频镜头后出现两端手柄。拖动按素材实际 PTS 吸附到源帧，预览对应边界帧并更新首末帧数值；松手提交一次 `trimClip`，主轨后续镜头自动接续。Esc、失去窗口焦点或指针捕获取消草稿；无变化不保存。既有前后逐帧按钮、数字入出点仍可用，聚焦手柄后左右键也可逐源帧调整。

比例尺在一次手势中固定，计算包含横向滚动位移。放大支持至 64 倍，靠近滚动区边缘自动滚动；时间轴尾部保留延长空间。至少保留一个源帧、不超出素材边界，并按剩余输出帧预算约束 60 秒工程上限。长素材/VFR 的源帧与固定 30 fps 输出帧有区别，不把移动距离直接当固定源帧率。

`src/trim.cjs` 是浏览器构建与 Node 测试共用的边界算法；构建时内联，不增加依赖。拖动期间只有本地草稿，松手通过原有 DSH Typert `copyEdit/mutate` 提交，携带起始工程 ID、revision、单次 operationId，复用服务端并发冲突与重放保护。临时窗口监听、指针捕获和滚动动画在取消、提交、卸载时清理。样式仍限制在插件 `.dce` 内；侧栏及主面板走原有 DSH slots，不增加宿主入口或旁路服务。

保存后旧修订的预览、导出入口失效。从当前源帧播放时，对新工程生成 360P 代理，之后由同一 video 连续播放全部后续镜头；1080×1920 / 30 fps 导出与代理使用同一工程计划。它仍是先准备代理的桌面预览，不是实时多轨渲染。

## 发现与修正

desktop.5 的最后一个镜头右端顶到视口，向右延长容易超出鼠标可操作范围。desktop.6 增加尾部空白，同步修改刻度/定位映射，八次正反拖动复验通过。首次自动化读取草稿早于 React 更新，改为等待可观察数值；一处快照调用参数不符合浏览器工具协议，改用有效调用。另一次把视频帧回调的首个样本当作起播点的断言失败，改核验真实 playing 事件并保留冷启动原观察，不伪装成一次全绿。安装器的宿主 peer dependency 提示保留，未为消除提示复制宿主依赖。
