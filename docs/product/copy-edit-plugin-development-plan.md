# 文案剪辑插件开发计划

版本：0.4 · 日期：2026-11-08 · 状态：最小插件与独立媒体任务基础已实现；调整为桌面业务优先、移动布局同步检查、手机性能后置。最新媒体复测仍有播放间隔未通过项。

上游文档：[PRD](copy-edit-plugin-prd.md) · [技术方案](copy-edit-plugin-technical-spec.md)。本稿复用 `build-checklist` 的规格引用、建设内容、验收和验证结构；本期不涉及黑客松提交。

用户已授权执行最小插件与隔离媒体试验，暂不做完整编辑器；随后仅恢复空闲现有 Android 模拟器操作。G0 最小范围通过；[首次失败](copy-edit-plugin-spike-report.md)与[后续修复](copy-edit-media-fix-report.md)分别保留。当前 4/60 秒成片准确性与缓存预览通过模拟器验证；直接合成预览、完整格式矩阵和实体手机仍未通过/未验证。生产宿主未接入媒体代码。下列勾选不外推超出实际验证范围。

## 1. 排序原则和交付边界

**当前排序覆盖下方较早的顺序依赖：** 按[桌面优先计划](copy-edit-desktop-first-plan.md)推进 T03 共享合同、T09 文案版本、T14 桌面提供方的最小能力，再形成桌面 T10/T11 的基础闭环；手机布局从页面开发起同步检查。Android T04/T08 的生产接入独立交付，T05–T07/T15 的真机矩阵与性能收敛后置。T11 的完整跨端验收仍保留原关口，但桌面子集不必等待 Android 性能全绿；T14 的首个提供方可先用静态黄金工程验证，不等完整 T11 UI。不是桌面做好后仅做 CSS 缩放。

11 月 7 日旧 APK 的 4/60 秒通过保留为历史；[11 月 8 日任务基础与回归](copy-edit-media-session-report.md)通过 11 项单测及版本/取消仪器化，但严格 4 秒整套复测有 183.4/266.7 ms 预览间隔超标，新 APK 的 60 秒未执行。不能沿用旧 APK 结果给新 APK 授予完整通过。

先证明能做准确的媒体处理，再做完整编辑器。不能先花大量时间画时间轴，最后才发现宿主没有导出能力。

1. 冻结当前 DSH / 宿主契约与工程模型。
2. 用最小真实插件验证接入，用小型原生验证界面证明逐帧、连续预览、1080p 导出。
3. 验证 WebView 与原生 Surface 的组合，再建设可长期维护的产品页面。
4. 接入公司资源、桌面提供方、团队复用，并完成真实端到端验收。

插件研发与 Android 媒体研发是两种职责；后者需要实际设备、编解码与图形管线调试经验。任务是工作包，不是“每项 15 分钟”清单。本稿不在设备、服务器协议和人员尚未确定时承诺固定工期。

## 2. 阶段、关口与产物

| 阶段 | 工作包 | 主要产物 | 退出条件 |
| --- | --- | --- | --- |
| P0：基线与插件合同 | T01–T03 | 目标清单、最小真实插件、版本化工程与 RenderPlan | G0 基础接入可复现，模型可驱动媒体试验 |
| P1：媒体可行性 | T04–T07 | 受控媒体桥、准确帧、连续预览、实际成片 | G1 / G2 / G3 分别给出通过或失败证据 |
| P2：移动整合与文案 | T08–T10 | 返回与 Surface 协作、文案闭环、多行 PNG 贴片 | 核心宿主回归通过，文案可独立试用 |
| P3：完整创作 | T11–T14 | 时间轴、公司资源、示例 / 团队库、桌面配套 | PRD 的编辑与复用流程连通 |
| P4：可靠性交付 | T15–T16 | 支持矩阵、恢复行为、插件包与测试报告 | 声明范围内 AT-01 至 AT-12 通过 |

T09 可在 P1 进行时独立推进，但完整时间轴 T11 必须等媒体关口。上述是实施依赖关系，不代表本轮已经启动并行开发。

**失败处理：** G1 失败先修时间映射与精确解码；G2 失败验证预混 / 代理预览并评审等待体验；G3 失败先找编码器、色彩、格式或合成原因。若需要另造完整底层引擎，重新估算工作量与范围。不得用服务器导出、仅关键帧剪裁或只播选中镜头代替失败项。

## 3. 工作包清单

### T01 冻结基线和验证材料

- [x] 完成基线记录与非生产验证准备（目标设备为本轮获准的 API 30 模拟器，实体手机未测）。

**规格引用：** 技术方案第 2、13 节；PRD 第 11、12 节。

**建设内容：** 记录当前分支、未提交状态、目标 APK / DSH / 移动插件与浏览器版本；核对实际 rc.2 API、目标机型及公司接口可用性。准备少量自制、无用户数据的帧号素材、带 B 帧 / 长 GOP 的样本、VFR、透明 PNG 和音画同步标记。确定每份样本摘要与预期时间关系。

**验收：** 不把历史 APK、官方最新文档或当前脏工作树混作同一基线；素材可重复生成，缺少目标设备时明确设备验收未开始。

**验证：** `git status --short`、运行时包成员与摘要核对；现有媒体工具若可用，检查真实 PTS / 轨道信息。依赖安装或大样本生成前执行第 6 节空间检查。本任务不操作生产手机。

**依赖 / 角色：** 无；集成人员负责。

### T02 创建符合 DSH 规范的最小插件

- [x] 通过正式包加载、侧栏、服务、工具及生命周期验证（最小只读工程，无模型调用）。

**规格引用：** 技术方案第 5 节；PRD FR-01、FR-17。

**建设内容：** 创建独立插件构建边界，锁定依赖；落实组合补丁、Host / Client 导出、root 主面板和侧栏注册。实现一个不依赖公司服务的只读对象查询，验证 Client→Host RPC 与工具调用返回相同对象身份。检查工具输出 schema 和 disposer。

**验收：** 用 rc.2 正式安装器接纳实际 pack 包；启用、停用、重启和重新启用不会重复注册，不改 DSH 核心文件，不带第二份 React / Cordis，不产生无认证旁路端口。

**验证：** 插件拟提供 `typecheck`、`build`、`test:contract` 和 `pack:check` 脚本，名称在创建时落实；用隔离 DSH profile 检查实际加载日志、入口导出、服务往返及释放。仅跑 mock 不记 G0 通过。

**依赖 / 角色：** T01；DSH / TypeScript 开发。

### T03 工程模型、时间语义与渲染计划

本轮仅实现最小只读模型、整数帧换算与试验 RenderPlan；CAS、撤销、持久化迁移仍未实现。

- [ ] 固定共享数据合同与编辑事务。

**规格引用：** 技术方案第 6、7、10 节；PRD FR-05、FR-12、FR-13。

**建设内容：** 实现 schema、整数帧 / 有理数时间、源 PTS 区间、RenderPlan、素材引用、版本 CAS、撤销命令和校验。定义切片、替换、空白区间、画布 / 帧率变更的行为。生成供 TS、Java 和桌面引擎共用的合同夹具。

**验收：** 边界、末帧、29.97 fps、VFR 映射、负数 / 溢出、冲突写入均有确定行为；同一工程计划可在不同适配器解释，旧版本不被新操作改写。

**验证：** 纯规则单测和黄金夹具，对照精确分数计算；不能用与实现完全相同的算法复制一份作唯一“期望值”。Android `util/` 新逻辑必须配对应单测。

**依赖 / 角色：** T01、T02；业务与媒体开发共同冻结。

### T04 Android 能力桥与素材注册

本轮用独立 Android 包验证媒体，只有接口草案和自制素材白名单；生产网页桥、来源/页面代次和任务服务尚未接入。

- [ ] 建立独立、受控的原生媒体服务边界。

**规格引用：** 技术方案第 4、10、12 节；PRD FR-08、FR-10。

**建设内容：** 新增 MediaProvider 接口和 Standard 实现入口，Low 提供明确不可用实现。探测真实编解码器；实现只接小 JSON 的命令路由、句柄注册、流式素材导入、任务记录及页面代次。复用现有来源 / 凭据边界，不将 3090 token 暴露给网页。

**验收：** 非法来源、旧页面、iframe、越界路径、符号链接变化、过大请求、未注册素材被拒绝；普通聊天与现有桥路由仍有效。能力未通过真实处理验证时标记 available 而非 verified。

**验证：** 路由、请求、路径和代次单测；仪器化文件句柄测试；Standard 编译与 Low 不加载 Media3 的构建检查。实际设备步骤待设备操作恢复授权后执行。

**依赖 / 角色：** T02、T03；Android 与桥接开发。

### T05 精确选帧与剪裁验证 G1

30 次原生选帧及 A/B 30 fps 的 4/60 秒完整成片通过。任意 B 帧/VFR/60 fps 到项目帧率的完整成片矩阵未完成，完整 G1 不勾选。

- [ ] 证明任意目标边界的画面和输出一致。

**规格引用：** 技术方案第 7 节；PRD FR-13、AT-07。

**建设内容：** 使用 T01 素材验证 Media3 / 原生解码的帧定位。实现请求合并、取消、PTS 识别、正反逐帧和有界缓存，区分源帧和项目帧。帧检查组件不能依赖完整编辑器 UI 才工作。

**验收：** 非关键帧入点、末帧、B 帧、VFR 和源 60 fps→项目 30 fps 都能解释并复核；画面未到达不能标记 seek 完成；迟到结果不抢播放头。

**验证：** 帧号图像 + 实际 PTS 记录 + 剪裁成片首尾对照；记录暖 / 冷响应和缓存峰值。单独写清代表帧 API 的适用范围；若不满足，验证定向 MediaCodec 解码路径。

**依赖 / 角色：** T03、T04；Android 媒体开发。

### T06 连续合成预览验证 G2

Surface 丢帧引发的 20 秒等待已修；直接合成仍有约 279–339 ms 接缝延迟，未通过。本地缓存路径 4/60 秒预览及 4 秒从下一帧起播通过，首次准备约 5/63 秒；实际屏幕/扬声器同步录测及其他设备未完成。

- [ ] 证明工程级播放和各轨道同步。

**规格引用：** 技术方案第 8 节；PRD FR-11、FR-12、FR-14、AT-06、AT-07。

**建设内容：** 锁定候选 Media3 版本；用静态 RenderPlan 搭建主视频、多镜头、PNG、字幕、配音和 BGM。先验证多音频，再测试一路叠加视频的多输入图；记录不同组合。实现原生全局时钟、下一片段预读及代次失效。

**验收：** 从中间播放继续至后续镜头，正确显示和混音；缺素材不跳过伪装成功。若要预混或代理预渲染，必须给出实际等待和失效行为；多轨 UI 本身不算通过。

**验证：** 真实设备 60 秒合成播放，记录卡顿、掉帧、声音标记误差、解码器数量和内存。修改中间片段后核对新旧计划，检查反复进入退出的资源释放。

**依赖 / 角色：** T03、T04；Android 媒体开发。T05 的帧检查用于定位问题。

### T07 原生 1080P 导出验证 G3

已修复模拟器 Surface 投递丢帧。4 秒 120/120、60 秒 1800/1800 帧，完整条码、PTS、两路混音与 PNG alpha 读回通过。仅为当前模拟器低复杂度夹具；实体手机、取消/空间不足等门禁未完成，完整 T07 暂不勾选。

- [ ] 生成可验证的手机本地成片。

**规格引用：** 技术方案第 7.4、9 节；PRD FR-15、AT-09。

**建设内容：** 同一 RenderPlan 经 Transformer 完成裁切、混音、PNG 合成、编码和 MP4 封装。明确强制重编码策略，禁不符合输出合同的静默 fallback；任务固定修订，输出先暂存后验证。

**验收：** 在列明设备本地生成真实 60 秒、1080p 显示画布的成片；核对旋转、帧内容、音频、透明边缘和实际编码器。取消、空间不足和编码失败不会产生假成功。

**验证：** 用独立解析 / 播放流程检查容器、解码画面、首尾帧和同步标记；记录耗时、内存、磁盘峰值及机型。可用 FFprobe 读取元数据，但元数据检查不能替代解码画面检查。服务器输出不计入本项。

**依赖 / 角色：** T03、T04、T05；Android 媒体开发。与 T06 共用合成定义，结果共同评审。

### T08 WebView 原生画面与统一返回

- [ ] 将已验证引擎接入实际工作台。

**规格引用：** 技术方案第 5.3、8.4、10.2 节；PRD FR-01、FR-02、AT-01、AT-12。

**建设内容：** 新增可释放的预览承载与可信 WebMessage 适配；在移动插件加入可选通用子路由返回协议。统一内部路由、系统返回、FAB 和重复侧栏点击，保留其他插件行为。

**验收：** 抽屉、弹窗、键盘、横竖屏、字体放大和错误页下不遮挡其他 UI；离开后不残留 Surface 或旧媒体声音。聊天草稿、工程播放头及子页面来源正确恢复。

**验证：** 实际主面板与浏览器，不只用独立 Activity；按仓库要求运行 `LayoutAuditInstrumentation` 相关 style 中英文、日夜、短屏、1.3 倍字体检查。补面板返回回归与旧页面消息拒绝测试。

**依赖 / 角色：** T02、T04、T06；移动 Web 与 Android 开发协作。

### T09 文案、版本与 AI 修改闭环

- [ ] 完成不依赖公司素材服务的文案使用流程。

**规格引用：** 技术方案第 5、6、11 节；PRD FR-03、FR-04、FR-05、AT-02。

**建设内容：** 分类、搜索、正文编辑、复制 / 粘回、版本、AI 建议采用、宿主模型选择、持久事务和冲突处理。默认无视频预览；没有 API 仍可使用本地功能。

**验证：** 存储崩溃恢复、并发修订和 UI 流程；模型先用合同替身做失败测试，再用获授权的真实服务核对一次链路，二者结果分别记录。

**依赖 / 角色：** T02、T03；插件业务开发。可在媒体验证进行时推进，但不证明媒体部分通过。

### T10 多行 PNG 贴片与字幕资产

- [ ] 实现可编辑源和可导出图片的一致性。

**规格引用：** 技术方案第 6.3、8 节；PRD FR-07、第 5.3 节、AT-04。

**建设内容：** 多行排版、颜色、描边、阴影、底色 / 背景图片和 Alpha PNG；源与 PNG 版本绑定、字体缺失处理、外部 PNG 导入；字幕 cue 及其渲染缓存。样式面板简洁，图片变换与源编辑区分。

**验收：** 三行文字、空行、描边和阴影不裁边；棋盘格不进入文件；深浅画面无异常底板。旧工程继续显示原贴片，导入扁平 PNG 不出现假的改字能力。

**验证：** 按 PRD 贴片六项验收逐项核对，并用 T06 / T07 预览和成片对照；记录字体与 PNG 摘要。不能只看浏览器 Canvas 截图。

**依赖 / 角色：** T03、T09；插件 UI 与图形开发。完整媒体一致性需 T06、T07。

### T11 可用的多轨时间轴

**验收：** 用户可完成“替换一个镜头、准确剪掉不满意画面、从此处继续试听、导出”；未使用轨道可收起，不改变相对顺序。无文案 / 配音 / 字幕的作品也成立。

**验证：** 同一真实工程在触摸和桌面输入下完成任务；结合帧号验证按钮动作不退化为改时间码。随机导航、保存重开和撤销后核对计划及素材原件未改。

**依赖 / 角色：** T05、T06、T07、T08、T10；前端与媒体开发。

### T12 公司检索、下载和生成服务

- [ ] 连通文案到候选再到工程的数据链。

**规格引用：** 技术方案第 10、11.2、11.3 节；PRD FR-08 至 FR-11、AT-05、AT-10。

**建设内容：** CompanyAdapter 能力探测、鉴权、按句检索、候选选择、下载核验、TTS / 字幕任务、状态重连和取消。模型与资源连接分离，下载可用性与候选相关性分离。

**验收：** 旧文案的迟到结果不覆盖新工程；不在已完成任务上重复收费重试；断网保留已下载资产和编辑。服务器不支持续传时从正确状态重新请求，不拼接不可信残片。

**验证：** 协议合同测试、延迟 / 断线 / 401 / 冲突 / unknown 情形，再连接实际公司服务进行端到端检索和生成。若真实接口缺失，只能标注联调未完成。

**依赖 / 角色：** T04、T09、T11，实际公司协议与测试权限；插件与后端开发。

### T13 完整示例、团队发布与可携带工程
