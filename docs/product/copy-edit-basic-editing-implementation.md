# 桌面基础剪辑实现与验收

2026-11-08，交付插件 `0.2.0-desktop.21`。仅修改 `plugins/dsh-copy-edit` 与本插件文档。沿用 DSH bundle、web client、slots/sidebar 注册和已认证 RPC，不修改 DSHA 宿主或接入 Android。

## 当前行为

| 操作 | 行为 |
|---|---|
| 分割 | 播放头处点击“分割”或 Ctrl+B；左右保留非空片段，可以独立选中、裁切、替换、前后移动、删除。分割以工程 30fps 帧为准。 |
| 删除中段 | 两处分割后选中中段，点击“删除片段”或在片段上按 Delete；主视频自动合拢，后续画面前移。没有普通删除留下间隙的模式。 |
| 撤销/重做 | 按钮、Ctrl+Z、Ctrl+Shift+Z / Ctrl+Y。每次操作及其文字、配音联动一起恢复。按工程持久化，最多 30 步、2 MiB；新编辑清除重做分支。文案版本、导入的素材文件不回退。输入框内保留文本自身快捷键。 |
| 视频与配音 | 视频操作默认把当前配音固定成独立音轨，不再以配音长度限制视频。分割后共享同一句配音，不重复播；删除画面也保留配音。独立面板可改工程起点、源起止范围、音量或明确删除声音。 |
| 声音超出画面 | 工程时长包含完整配音，明确提示“只有声音，需补充画面”；预览与导出使用黑色尾段，不暗中截断配音或复制末帧。BGM 按完整工程时间循环。 |
| 文字绑定 | 新文字默认绑定选中分镜；旧绝对时间贴片保持原行为。绑定保存 clipId 与局部显示区间，移动跟随、裁切取保留交集、替换保持关联；跨分割点拆为两条并保持上下层顺序。删除画面移除该片段的绑定文字，撤销恢复。 |
| 文字手动时间 | 属性数字、时间轴两端拖动及手柄方向键仍可使用。绑定时区间位于对应分镜内；选择“固定在时间轴”可跨分镜显示。“覆盖当前镜头”恢复全镜头范围。 |

视频必须位于源素材内且非空，画面与声音工程总长仍不超过 60 秒。这些限制与配音最短长度无关。当前最多 120 个片段、120 条文字，仍是单主视频轨；没有新增拖动排序、复制粘贴、多视频叠加编辑或完整字幕编辑器。

## 实现边界

- `src/timeline.mjs`：浏览器与提供方共用时间换算。分割保存共同解码窗口及输出帧偏移，避免 25fps/VFR 分别取整添帧；不修改原视频。
- `src/project.mjs`：原子命令、分割/绑定联动、独立配音与冻结媒体计划。替换按工程输出帧预算选择源窗口，短片段也能替换。
- `src/store.mjs`：编辑快照与项目状态同事务提交，保留修订冲突和请求重放检查。失败操作不写半份历史。
- `src/client.cjs`、`editor-tools.cjs`、`sticker-gesture.cjs`：工具栏/快捷键、绑定选择、独立声音编辑、手柄边界。首页布局不变，仅让时长包含保留的声音尾段。
- `src/desktop-media.mjs`：同一冻结计划生成预览和导出；剪辑窗口按输出帧裁切，声音不足画面补静音、画面不足声音补明确的黑色尾段。过滤图使用任务文件，避免片段数增大后超过 Windows 命令行长度；任务结束删除过滤图。

## 已执行验收

1. 最终 47 项测试全部通过，0 失败、0 跳过，类型检查和打包通过。包含真实 FFmpeg 编码、帧序列、音频、文字显示边界，以及历史持久化、失败原子性、重放与版本保护。
2. 25fps 标记素材先渲染基准，再切两刀，逐帧对比无添帧/丢帧；删掉中段后仅保留指定画面序列。短画面配长声音时保留完整配音、黑色尾段帧数准确；预览和 1080P 的解码音频相同。
3. 浏览器实际用已有公开咖啡素材，新建独立验收工程。10 秒画面在 3 秒、6 秒分割，删除中间段得到 7 秒；按钮撤销及快捷键重做恢复相同片段 ID、文字和声音数据。
4. 实际拖拽镜头尾端，把 3 秒画面裁至 2 秒，4.2 秒配音保留；撤销后将后一镜头替换为 25fps 素材。文字手动区间及拖动末端、镜头前移联动、删除后声音尾部提示均完成检查。
5. 最终文件：1080×1920 / 30fps / 7 秒 / 210 帧；预览 360×640 / 210 帧。两份 48kHz 立体声解码音频 SHA-256 相同：`7b6d40a0bb9b7f626af0a8447156f110729ac6034aa8ebe6fdd55856033f8a57`。配音、衔接和 BGM 循环边界的 8 个采样点相关度均高于 0.9998、测得滞后 0 样本。AAC 解码包含帧填充，336896 样本不冒充 7 秒的精确有效样本数；容器音轨时长为 7 秒。
6. 实际从头预览及从 2.8 秒续播到结束，浏览器报告掉帧 0、无 waiting/stalled/error。该浏览器的帧回调较稀疏，不能据此宣称逐帧显示流畅度或全部机器性能已证明；本轮没有新做 60 秒性能对照。现有“先生成代理，再连续播放”方式保留。

失败与纠正保留：首次黑色尾段编码的帧数门禁失败，定位为 concat 后帧率信息不足，改成显式 30fps 与整数补帧后通过；同版本 tgz 安装显示 up-to-date 但文件摘要仍旧，改发 desktop.21 后逐文件匹配；一次浏览器续播脚本在定位准备期间点击了取消准备，等待超时，核对状态后待准备结束续播成功。不是一次连续全绿记录。
