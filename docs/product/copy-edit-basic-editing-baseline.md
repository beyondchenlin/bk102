# 桌面基础剪辑核查与补齐基线

> desktop.21 更新：本页保留当时规则/差距快照。分割、删除中段、撤销重做、独立保留配音和分镜文字绑定已实现；当前行为与实际验收见 [桌面基础剪辑实现与验收](copy-edit-basic-editing-implementation.md)。原先以配音长度限制视频的规则已取消。

2026-11-08，核查对象 `dsh-copy-edit@0.2.0-desktop.19`。本轮根据用户要求先检索官方资料并对照源码；本文是缺项与开发验收基线，不是新功能已完成的回执。此前已授权的分镜文字绑定、分割与裁切规则修正仍待实现，Android 不在范围内。

## 查到的操作语义

- CapCut 官方把分割定义为在指定位置把片段变成可独立编辑的部分，本身不删除素材。移到两个边界分别分割，再删除中间段，才是删除中间内容的流程。[CapCut 分割说明](https://www.capcut.com/features/how-to-split-a-video-capcut-workflow)
- Premiere 官方基础编辑包含拖两端裁切、剃刀分割、拖动位置、删除、逐帧定位，并说明时间轴编辑不改动源媒体文件。[Adobe 基础编辑](https://helpx.adobe.com/premiere/desktop/edit-projects/intro-to-editing/edit-video-in-premiere.html)
- 普通删除与波纹删除不同：前者可能留下空隙，后者同时关闭空隙、让后续片段前移。[Adobe 删除规则](https://helpx.adobe.com/premiere/desktop/edit-projects/change-clip-sequence/remove-clips-from-a-sequence.html)
- 视频和音频可以联动编辑，也可以解绑后独立编辑。Apple 同样提供音频分离，分离后作为音频片段移动、修剪和处理。[Adobe 联动与解绑](https://helpx.adobe.com/premiere/desktop/add-audio-effects/basic-audio-editing/link-audio-and-video-clips.html)、[Apple 分离音频](https://support.apple.com/zh-cn/guide/imovie/mov267936bb2/mac)
- 时间轴吸附可帮助对齐其他片段、标记与播放头；它不等于磁性主轨自动填补空隙。[Adobe 吸附](https://helpx.adobe.com/premiere/desktop/edit-projects/change-clip-sequence/snap-clips.html)
- 剪辑撤销/重做恢复编辑动作；不是恢复某个文案版本，也不是防重复请求记录。[Adobe 编辑历史](https://helpx.adobe.com/premiere/desktop/edit-projects/correct-mistakes/view-or-make-changes-in-the-history-panel.html)

以上是官方功能事实。下面的优先级和联动默认值是针对本项目业务作出的设计判断，不声称所有编辑器都采用相同默认行为。CapCut 国外桌面版说明不能外推所有剪映版本和快捷键完全相同。

## 当前差距

| 能力 | 最低可用行为 | 当前源码状态 |
|---|---|---|
| 素材与工程 | 导入、选择、缩略图、保存、重新打开 | 已有；不是缺分割的原因 |
| 定位与播放 | 拖动播放头、放大/滚动、逐帧、从当前位置连续播放 | 部分已有；源素材逐帧与工程时间轴操作仍分开，缺完整快捷键与片段吸附 |
| 两端裁切 | 独立调整素材入出点，保留未被破坏的源素材 | 已有；配音长度被用作额外强制最短视频长度 |
| 分割 Cut/Split | 在播放头切成两段，两段能独立选择、剪短、替换、移动、删除 | 缺失；没有 splitClip 命令或工具栏入口 |
| 删除中间段 | 分割两次后删除中段；明确是保留间隙还是自动合拢 | 只有删除整镜头并拼接剩余数组；缺中段分割及显式间隙规则 |
| 排列与复用 | 拖动排序、插入、复制/粘贴、复制片段、替换素材 | 替换和前移/后移按钮已有；没有拖动排序和片段复制操作 |
| 撤销/重做 | 裁切、分割、删除、移动、文字修改及联动结果可以整步恢复 | 缺失；文案版本与 operations 请求去重不能替代它 |
| 声音 | 原声、配音、BGM 清楚区分；音频可独立裁切/移动、调音量、静音；可联动/解绑 | 有配音/BGM 合成和句子绑定；源视频原声固定静音；没有可独立编辑的完整音频时间线 |
| 文字 | 多条内容/位置/大小/时段；绑定或解绑分镜；剪切后保持归属 | 多贴片编辑已有；当前只有工程绝对时间，没有 clipId 关联 |
| 画面基础处理 | 图片/视频的缩放、位置、画幅裁剪、旋转等 | 当前主视频主要固定等比适配画布；不能把它称为完整画面编辑 |
| 字幕与叠加 | 真正可操作的字幕/图片轨，支持各自起止范围 | 仍是预留轨道位置，不是已实现的多轨编辑能力 |
| 预览与导出 | 各种编辑后音画/文字一致、帧数正确、保存重开一致 | 已有有限样本证据；不能由此推出基础编辑功能齐全 |

基础版本应先补齐剪切、删除、排列、撤销、联动与解绑；波形、淡入淡出、画面变换、字幕编辑随后形成完整基础工作流。复杂关键帧、调色和高级特效不作为本次分割与联动改造的前置条件。

## 为什么当前裁切受限

`src/client.cjs` 的 `useTrimGesture` 将绑定配音时长换算成 `minFrames`；`src/project.mjs` 的 `compilePlan` 再拒绝比该配音短的镜头。两处共同造成拖不动或保存被拒绝。这是上轮“保护配音完整”的具体实现，不是媒体引擎无法分割视频，也不是通用编辑器必须把音频时长当作视频下限。

仍需保留的有效边界包括：视频不能引用素材之外的帧、不能形成零长度片段、分割点必须在片段内部。当前 60 秒/30 镜头是原型范围和资源上限，不属于剪辑原理；增加分割后还必须复核数量限制，不能把合法的短片多次切段卡死。

当前工程将配音直接放在单个 clip 的 narration 内，起点由该 clip 决定。只删掉 `minFrames` 和后端检查，会引出跨镜头配音重叠、工程尾部截断和删除配音归属问题；这不等于完成自由裁切。应先引入能保留声音的独立排程，再替换不可绕过的时长保护。

## 本项目应采用的联动规则

以下是后续实现要求，尚未发布：

1. **只剪画面与联动剪切分清。** 外加配音允许在独立音频轨上跨多个画面继续播放；用户明确选择联动剪切时，相关片段才按同一时间点处理。不能默默丢弃配音、重复播放整句、加速声音或补冻结画面来掩盖冲突。
2. **分割不会损失内容。** 分割前后总长度、帧顺序和声音应保持；25fps/VFR 源转换为 30fps 时，需要共享原输出时间映射，避免两段分别取整后凭空多一帧。
3. **文字绑定到分镜身份。** 移动镜头时跟随，替换素材时保留关联；镜头缩短后显示范围不得落到无关镜头。手动起止范围继续有效，用户可以选择解绑并固定在工程时间轴。
4. **分割时重新分配文字。** 只在左侧或右侧出现的文字归属对应部分；跨越切点的文字在两侧保留正确范围，不重复叠印、不掉一帧。需要为两段分别编辑保留独立身份。
5. **删除和收拢是明确操作。** 本项目的单主轨拼接可以默认自动收拢；绑定文字随所属片段处理，非绑定元素依所选联动规则处理，BGM 不因每个镜头起点重新循环。保留间隙不能伪装成已支持。
6. **操作必须可恢复。** 一次分割或删除涉及的视频、文字和声音变化作为同一次编辑；撤销/重做恢复整次关联变化，不回滚 API Key、素材文件或无关文案版本。键盘快捷键只在编辑区生效，输入文字时不能误剪视频。

配音长于视频时，既不能一律禁止剪画面，也不能悄悄截掉尾音。独立音频超出画面尾部时必须让用户看得见，明确成片范围/补画面决策；当前不会通过隐藏的黑帧或冻结帧自动“解决”。

## 接下来开发与验收顺序

1. 建立可撤销的编辑事务与清楚的媒体/联动关系，保证旧工程只读不改写。
2. 实现播放头分割、删除中段、复制/排列和配音独立排程，撤掉由配音长度造成的不可绕过视频裁切限制。
3. 实现文字绑定/解绑及分割、裁切、替换、移动、删除的联动；保留手动时间调整。
4. 用真实素材验收：10秒片段在3秒和6秒各切一刀，删除中间3秒，首尾连续播放；撤销恢复10秒、重做回7秒。再覆盖含配音和跨切点文字的情况，检查不重复音频、BGM连续、文字不串镜头。
5. 最后核对预览、1080P成片和保存重开的同一工程状态；范围保持桌面端，不改宿主或 Android。
