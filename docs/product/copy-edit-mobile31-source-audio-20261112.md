# mobile.31：完整视频、原声与预览合成

2026-11-12，承接 mobile.30。用户反馈视频原本有声、预览无声，2913源帧只进入约5秒工程，播放卡顿。截图本身不能证明源文件损坏或手机解码性能。

## 原因和修复

- `addClip` 原来默认取前4秒，改为完整源窗口；工程、裁切、草案契约和原生执行限制同步改为18000输出帧/10分钟。旧工程不自动改写已裁切范围，镜头属性的“使用完整素材”明确恢复完整窗口，可撤销。
- 原生视频序列移除了原声，且没有单独加入源音轨；桌面仅混合配音/BGM。两端现在保留真实源音轨，支持每镜头0–100%音量。按原始窗口相位截取声音，VFR分割不以向前取整的画面PTS作为音频入点。旧素材记录缺少`hasAudio`时仍从实际媒体确认。
- 原生混音按同时活跃音轨的增益和统一预留峰值，保留相对音量。桌面保留原限幅器，并把MP4电影时间基设为48000，避免非整秒音轨被毫秒级edit list截短。
- 源帧滑块与计数随当前播放镜头/位置更新。暂停后逐帧操作从当前显示源帧开始。
- Android预览直接在360×640画布合成，贴片按比例缩放，省去先合成1080p再缩小的步骤。导出仍1080×1920。原生缓存契约升至v6，桌面升至`desktop-ffmpeg-av7-source-audio`，不复用旧语义结果。
- 单个成片/分享流的上限同步为512MiB；单源256MiB、会话素材512MiB、源PTS数量及前台生命周期等既有边界保留。未承诺任意10分钟高码率素材一定通过。
