# 文案剪辑插件 PRD

版本：0.1 · 日期：2026-11-07 · 状态：需求评审稿，未进入实现验收。

配套文档：[技术方案](copy-edit-plugin-technical-spec.md) · [开发计划](copy-edit-plugin-development-plan.md)。两者是待验证的实施方案，不改变本 PRD 已确认需求。

本文件汇总本次讨论已经明确的需求，并为尚未决定的细节提出可修改的默认值。它不代表功能已经开发或通过手机验收。本文统一使用官方名称 **DeepSeek Harness（DSH）**；移动宿主为 DSHA 及本工作区的 BK102 分支，宿主品牌不因插件而改变。

编写方式：复用本机 `build-prd` 技能的用户故事、验收条件和边界情形方法。未找到独立命名为 `PRD-Skill` 的技能；本项目不属于黑客松，不引入该技能的报名、提交和状态文件流程。

## 1. 产品定义与范围

为公司的短视频创作提供一个可安装、可停用的 DSH 插件。用户从文案库选取、修改和保存文案，按需匹配公司素材或导入本地素材，进入可逐帧操作的多轨剪辑工程，最后在具备支持能力的手机或桌面环境中导出成片，并将文案及完整工程用于团队复用。

**产品形态：同一个插件、同一套业务与工程数据，按屏幕布局和平台能力适配。** 桌面不是独立重做的一套系统，手机也不是把桌面界面等比缩小。文件访问、触摸、系统返回、媒体解码、后台生命周期和导出能力需要单独适配。

### 1.1 已确认的产品决定

| 决定 | 要求 |
| --- | --- |
| 入口 | 宿主侧栏只增加“文案剪辑”；普通聊天不增加常驻的文案、剪辑标签 |
| 首页 | 上下两个卡片：文案在上、剪辑在下；分别进入文案库和工程列表 |
| 文案默认展示 | 正文、贴片、可选 BGM；默认不显示视频案例或播放器 |
| 新手学习 | 文案详情有直接可见的“打开完整示例工程”，进入工程后播放、试听全套效果 |
| 文案使用 | 支持复制到外部 AI 修改后粘回，也支持配置模型后在插件内对话修改 |
| 版本 | 文案按 V1、V2 等保存，工程绑定明确版本；团队可复用 |
| 贴片 | 以可多行排版的透明 PNG 图片呈现，支持文字颜色、描边及可选背景图、背景样式；不等同于单行字幕 |
| 素材来源 | 公司服务器检索下载与用户自主导入都成立；已假设服务器完成视频向量化 |
| 剪辑 | 逐帧调整、连续预览、主视频拼接及多轨支持；贴片和字幕在视频上方，声音在下方 |
| 成片目标 | 主要为一分钟以内、最高 1080p；手机本地导出是核心目标 |
| 连接方式 | 个人模型 API 与公司服务分别配置；公司服务可同时提供模型、检索、配音等能力 |
| 设计 | 干净、少文字、少层级；不靠标语和次要标签解释布局 |
| 商业系统 | 本期不做会员、订阅、付费等级 |

### 1.2 本稿提出的默认值

以下为实现评审起点，不能当成用户已指定的参数：新工程默认竖屏 9:16、30 fps；主视频默认无缝拼接；第一阶段不做实时多人共同编辑，采用版本和冲突副本；示例原件只读，点击“复用”后生成个人副本。输出封装、编码、码率、支持机型和并发数由技术方案与实测确定。

### 1.3 用户与成功条件

| 用户 | 主要任务 | 成功的可观察结果 |
| --- | --- | --- |
| 熟练员工 | 查找文案、快速修改、替换少量素材出片 | 不播放案例也能找到和复制正文；返回工程后保留编辑状态 |
| 新员工 | 学习文案与画面、贴片、配音和 BGM 的关系 | 从文案打开完整示例，连续播放所有轨道，复用后不改坏原件 |
| 内容维护人员 | 发布可复用文案和工程 | 团队成员获得明确版本及完整依赖；缺失素材可定位 |

首个完整版本的成功条件是完成第 11 节的真实端到端流程。不得用“界面能打开”“插件安装成功”代替检索、剪辑和导出成功。

## 2. 信息架构与页面职责

```text
DSH 侧栏 / 手机侧栏抽屉
└─ 文案剪辑
   ├─ 文案卡片
   │  └─ 文案库 → 文案详情 / 编辑 / 版本
   │                 ├─ 打开完整示例工程
   │                 ├─ 匹配素材 → 创建工程
   │                 └─ 打开关联工程
   └─ 剪辑卡片
      └─ 工程列表 → 时间轴编辑器
                       └─ 查看关联文案（定位具体版本）
```

首页两个卡片均可带最多一条最近记录，直接继续指定文案或工程。卡片用名称和内容预览表达用途，不写宣传语。真实任务产生结果时，可提供“打开此工程”等对象入口；不因此增加全局聊天工具条，也不在任务完成后强制切换页面。

| 页面 | 手机 | 桌面 | 共有规则 |
| --- | --- | --- | --- |
| 插件首页 | 两个卡片纵向排列 | 保留上下顺序，控制内容宽度 | 不增加第三类业务入口填满空间 |
| 文案库 / 详情 | 列表进入详情，编辑和 AI 对话按需展开 | 列表与详情并列，AI 区按需打开 | 默认无视频缩略图、视频播放区域 |
| 工程列表 | 紧凑列表、新建、导入、继续 | 可增加列表信息密度 | 明确工程名称、修改时间及关联版本 |
| 编辑器 | 上部预览、中部播放控制、下部时间轴，属性按需展开 | 素材、预览、属性可并列，时间轴在下方 | 同一工程、轨道顺序和编辑命令 |
| 贴片编辑 | 多行文字编辑与图片预览，样式区可收起 | 预览与样式并列 | 以透明画布中的图片结果为准 |

顶部标题和必要操作优先；次要操作进入菜单。返回按钮、版本选择、轨道名称、真实任务进度及错误原因属于操作信息，不按“砍提示文字”删除。

## 3. 核心用户旅程

**熟练员工处理文案：** 侧栏进入 → 搜索或选分类 → 打开文案 → 复制正文到外部 AI，或在插件内修改 → 检查结果 → 保存新版本。整个过程无需下载视频、连接公司资源或创建剪辑工程。

**新员工学习：** 文案详情 → 打开完整示例工程 → 从当前播放位置连续试听成片 → 查看对应文案与轨道 → 复用生成自己的工程 → 替换素材并保存。缺失示例时不提供假按钮；维护人员可以补关联。

**公司素材创作：** 确认文案版本 → 匹配素材 → 按句子 / 分镜查看候选及关联片段 → 选择并下载 → 创建可编辑工程 → 按需请求配音、字幕或选择 BGM → 逐帧调整、预览 → 导出 → 自主决定是否发布到团队库。

**离开局域网继续：** 打开已下载工程 → 使用本地素材编辑 → 使用个人 API 修改文案（有网络时）或手动修改 → 本地导出。返回公司网络后再同步。未下载的公司素材只显示缺失状态，不伪装为可离线使用。

**直接剪辑：** 剪辑卡片 → 新建 / 导入素材 → 添加贴片和 BGM → 编辑、导出。没有文案、配音和字幕也可成立。

## 4. 用户故事与验收条件

下列 `FR-xx` 为本 PRD 的需求编号，不是现有代码接口名。

### FR-01 插件入口与独立性

作为用户，我希望从现有侧栏进入功能，而不改变普通聊天的使用方式。

- 启用后侧栏仅出现一个“文案剪辑”入口；桌面折叠时沿用宿主图标方式，手机通过宿主抽屉进入。
- 插件首页打开在宿主主面板；文案或剪辑工作台不保留普通聊天输入框。
- 没有当前会话时仍能进入插件；需要工作区或保存位置时再让用户选择。
- 停用后移除入口、注册和事件监听，不删除文案、工程、素材或宿主聊天数据。

### FR-02 一致的返回与状态恢复

作为用户，我希望返回到刚才的上下文，切换页面不丢编辑。

- 界面返回、Android 系统返回和宿主面板返回使用一致规则；先关闭当前弹层，再回子页面来源，最终回宿主。
- 从文案进入示例或关联工程，返回到原文案及原版本；从工程列表进入编辑器，返回原列表位置。
- 文案草稿、工程修订、播放头和任务身份持久保存；组件卸载、横竖屏变化不清空已保存状态。
- 正在输入的尚未落盘内容在离开前保存或明确处理；不能只显示“已保存”而没有保存成功。

### FR-03 文案库与默认展示

作为熟练员工，我希望优先看到可用的文案内容。

- 支持按分类、关键词查找，区分个人与团队来源；无结果提供清除筛选或新建操作。
- 列表以标题、正文摘要为主；详情包含完整正文、贴片图片预览、可选 BGM 和版本入口。
- 默认不加载、自动播放或显示视频案例。查看案例由“打开完整示例工程”触发。
- 模板可复制并修改，不要求填写一套固定表单才能写文案。

### FR-04 外部修改与内置 AI 修改

作为员工，我希望选择熟悉的修改方式。

- “复制正文”取得纯文本；另提供明确的“复制全部文本”，可包含贴片的可编辑文字，不能把图片地址当作正文复制。
- 外部修改后可粘贴为草稿或新版本，原已保存版本不被覆盖；无需接入豆包等外部服务的账号。
- 配置可用模型后能围绕当前文案对话修改；AI 建议经用户采用后才进入文案版本。
- 未配置 API、额度不足、超时或取消时保留原文与已获得结果；手动编辑、复制及本地版本功能仍可使用。
- 模型来源可选择个人或公司；切换失败不静默改用其他服务、发送给其他提供方或覆盖宿主默认模型。

### FR-05 文案版本与工程绑定

作为员工，我希望知道用的是哪一版，并能回看和复用。

- 已保存版本有稳定身份、V1/V2 等显示编号、创建时间和来源；工作草稿可自动保存，正式版本不可静默改写。
- 可以查看历史、比较正文和贴片变化，并从历史另存新版本；“恢复”不删除后来的版本。
- 工程绑定具体文案版本、贴片资产版本及配音来源。文案有新版时由用户选择是否更新工程。
- 更新文案后标记可能失效的镜头匹配、配音和字幕，仅在用户执行相应操作时重算；保留手工剪裁和已确认素材。

### FR-06 完整示例与复用

作为新员工，我希望看到可学习的完整工程，而不只是一个成片文件。

- 有关联示例的文案详情直接显示“打开完整示例工程”，不藏在多级菜单；进入后显示对应时间轴及全轨预览。
- 完整示例包括文案版本、镜头顺序、剪裁点、贴片、字幕、配音和 BGM 中实际使用的内容；不强制每例包含全部轨道。
- 只读预览不改写示例；“复用”生成独立工程和可编辑引用，用户改动不会修改团队原件。
- 缺素材、权限失效或格式不支持时标记具体项；仍能阅读工程结构，不能把不完整预览标成完整成功。

### FR-07 贴片是透明图片资产

作为创作者，我希望贴片呈现完整的文字设计，能多行、有描边，也能继续修改。

- 贴片在库、编辑器和视频中均以图片视觉结果展示；不是强制单行文本框，也不是字幕轨的别名。
- 插件创建的贴片同时保存可编辑源和渲染后的 RGBA PNG；可编辑源包含多行文字、排版和样式。详见第 5 节。
- 支持导入现有透明 PNG。没有源文件的图片可以变换、裁切或替换，但不得承诺直接改其中已栅格化的文字或颜色。
- 源内容修改生成新的贴片版本和对应 PNG；历史文案和工程继续引用原版本，除非用户明确更新。

### FR-08 模型与公司资源分别连接

作为用户，我希望在任何地点配置自己的模型，并在公司网络获得资源能力。

- 个人模型、公司模型、公司素材与生成服务分别报告能力和连接状态；填写个人 API Key 不等于已连接公司资源。
- 未连接公司服务器不阻止进入插件、查阅本地库、编辑已有工程和自主导入。
- 连接地址、身份配置集中在设置或操作时的配置入口，不在每页常驻展示 API 字段。
- 本期不做付费会员；团队资源仍有访问和发布权限。未认证不能读取他人私有文案或工程。

### FR-09 文案检索素材与人工选择

作为创作者，我希望按文案找到相关画面，并保留最终选择权。

- 以选定文案版本和分镜意图发起检索，候选关联到具体句子 / 分镜，记录素材身份及建议范围。
- 提供候选预览、替换、选中和下载；“一键匹配”可生成可调整的初稿，不把相似度等同于正确素材。
- 部分句子无候选时可重写查询、手动导入或跳过，不丢弃已选部分。
- 用户后来换文案或切工程，迟到结果仍归原任务；不覆盖当前另一份文案或工程。
- 视频已向量化是服务前提；插件消费检索接口，本期不承担重新建设服务器向量化系统。

### FR-10 素材下载与自主导入

作为用户，我希望使用公司素材，也能导入手机或电脑文件。

- 通过平台文件选择入口导入视频、图片、音频；在导入时检查可读性和可处理能力。
- 下载有进度、取消、失败重试及磁盘空间判断；可恢复下载须由服务器协议支持，不能假设所有来源都支持断点。
- 开始剪辑前明确哪些素材已本地可用；源文件移动或授权失效可重新定位，不能覆盖其他素材。
- 工程剪裁不修改原媒体文件；缓存可以重建，用户原素材不作为缓存删除。

### FR-11 配音、字幕与音乐

作为创作者，我希望按需补齐声音，也能只用画面、贴片和 BGM。

- 请求公司配音服务时绑定文案版本和声音选项，返回后可试听、采用或重新生成。
- 字幕独立于贴片；字幕可编辑内容与时间，不因贴片改行数而自动改变。
- 支持导入配音及选择 / 导入 BGM，调整起点、音量和静音；超出项目部分可剪裁。
- 没有配音或字幕仍可预览、导出。服务失败不阻止其他本地编辑。
- 文案、配音和素材时长不一致时显示需要调整的对应段，由用户决定裁切、补镜头或重新配音；不静默加速或截断台词。

### FR-12 多轨工程与清晰顺序

作为熟悉手机剪辑的用户，我希望沿用直观的时间轴。

- 时间轴从上到下为：**贴片 → 字幕 → 叠加视频 / 图片 → 主视频 → 配音 → BGM**。同类内允许必要的多个素材片段。
- 主轨支持拼接、调序、分割、剪裁与替换；叠加轨支持图片或视频的区间和基础变换。首版不承诺不限层数。
- 未使用的可选轨道可收起；新增时出现在正确位置，不能把音频放到视频上方。
- 明确选中片段、播放头、缩放与静音状态；操作对象不能靠颜色单独区分。
- 支持撤销、重做及保存后重开；媒体替换后保留可保持的区间与变换，超范围部分明确处理。

### FR-13 逐帧定位与剪裁

作为剪辑者，我希望准确保留某一帧，而不是只能拖动到大致秒数。

- 提供可触摸的“上一帧 / 下一帧”按钮，单击分别移动项目时间基准下的一帧；边界不越界。
- 播放头移动与设定入点 / 出点是不同操作。用户可先检查目标画面，再设定剪裁边界。
- 时间码提供帧位；支持时间轴缩放，但帧按钮不依赖用户先把时间轴放得足够大。
- 对可变帧率、混合帧率素材，技术方案必须确定源时间戳到项目帧的映射；不能用浮点秒数近似后宣称逐帧准确。
- 验收使用有连续帧号的测试视频，对照预览、设定边界和最终导出帧；仅跳转关键帧不算通过。

### FR-14 从当前位置连续预览

作为用户，我希望从正在调整的镜头继续看下去，判断衔接是否自然。

- 默认播放从当前工程播放头开始，继续播放后续镜头，直至工程结束或用户暂停。
- 贴片、字幕、叠加、配音及 BGM 按统一工程时间混合；不只播放选中源片段。
- 后续内容预加载；若缺少素材或解码失败，在具体位置说明原因，不用黑帧或跳过片段伪装完成。
- 调整剪裁、替换素材后预览使用新工程修订，失效的预加载内容不能继续播放。

### FR-15 本地导出

作为用户，我希望一分钟以内的作品能在手机端完成制作，无需再交给电脑。

- 核心目标为最高 1080p 的本地导出；导出前探测设备、媒体与输出能力，并检查可用空间。
- 导出绑定确定的工程修订，包含所有可见轨道及未静音音频；导出期间继续修改产生新修订，不污染正在生成的成片。
- 显示进度、取消及结果文件；失败保留工程，不把不完整文件显示为成片；用户能选择平台允许的保存 / 分享位置。
- 不支持 1080p 或遇到不支持格式时说明实际限制，可让用户选择已验证的其他方案，不能静默降清晰度。
- 服务端导出未来可作为可选能力，但不能代替本地导出目标或据此宣称手机导出验收完成。

### FR-16 团队发布与复用

作为团队维护人员，我希望成片和可复用工程与文案一起沉淀。

- 用户主动发布文案版本，可同时附成片与完整工程；发布前列出缺失媒体及需上传的依赖。
- 工程包区分实际随包媒体、公司资源引用与缺失资源；存在引用不等于素材已经上传或可供接收者使用。
- 成片只能用于观看；只有具备完整工程结构和可访问依赖时才标为“完整示例”。
- 并发更新基于原版本校验，冲突保留双方副本，不以最后写入静默覆盖；可建立新团队版本。
- 发布失败可恢复到同一次任务；不重复建立同名版本。个人 API Key、连接令牌和本机路径凭据不随工程发布。

### FR-17 AI 工具与界面使用同一业务结果

作为用户，我希望自然语言请求产生的文案和工程能直接在界面中继续编辑。

- 模型工具与 UI 使用同一套文案、版本、工程、素材和任务身份；“打开工程”指向工具实际生成的对象。
- 工具可提供查找文案、提出新版本、检索素材、创建工程和查询任务等明确能力；修改范围与用户意图相符。
- 导出、外发 / 团队发布等操作由用户明确发起或已有明确授权触发，不因一句泛化创作需求自动执行。
- 查询能返回处理中、完成、失败、取消、结果未知；未知写入结果先核对任务，不盲目重放收费生成或发布动作。
- 工具在官方工具体系注册并随插件生命周期释放；不以模拟点击坐标作为业务接口。

## 5. 贴片详细规格：可编辑源 + PNG 成品

本节是用户最新纠正，优先于此前效果图中看起来像单行文本的表现。**不重新生成已有效果图；后续设计与实现按本节执行。**

### 5.1 素材模型

| 部分 | 内容 | 用途 |
| --- | --- | --- |
| 可编辑源 | 多行文字、字体及字重、字号、文字颜色、描边、阴影、对齐、行距、字距、内边距、画布尺寸、背景设置 | 后续再次修改文字和样式 |
| PNG 成品 | 具有 Alpha 通道的 RGBA 图片，保留完整文字、描边、阴影和背景图结果 | 库中预览、工程合成和导出 |
| 工程实例 | 指向确定素材版本，另有位置、尺寸、旋转、不透明度、入点、出点及层级 | 同一贴片可用于不同作品而不改素材源 |
| 外部 PNG | 原始图片及可用的来源信息，可无可编辑源 | 支持导入既有贴片，不假定能还原字形和文字 |

透明指画布未绘制区域透明，文字本身可以完全不透明。可选背景包括纯色、背景图片及其透明度；选择了有底色样式时，该部分不透明是正常结果，不应强行去掉。编辑器的棋盘格只是透明度提示，不进入 PNG 或成片。

### 5.2 编辑与预览行为

- 保留用户换行，并支持自动换行；修改宽度时即时预览真实排版，不强制挤成一行。
- 首版支持一份贴片的整体文字样式和多行布局；逐字动画、复杂富文本、动态贴片属于后续能力。现有 PNG 中的复杂设计可直接导入。
- 样式调整不直接覆盖已保存 PNG；保存时产生对应版本，生成失败保留原资产及编辑草稿。
- 预览可切换浅色 / 深色底或当前视频帧，便于判断浅色文字、深色描边与透明边缘。
- 文字、描边和阴影完整包含在图片有效边界内；缩放或导出不得裁掉外沿，不得出现黑边 / 白边污染。
- 字体缺失时使用已有成品保持原预览；继续编辑需要选择可用字体，替换后先预览，再生成新版本。不得悄悄换字体造成断行漂移。
- 文案页同时保留贴片图片预览和可复制的源文字（存在时）；图片预览不属于默认展示视频案例。

### 5.3 专项验收

1. 三行中文、不同长度行、带标点和空行的贴片，在文案详情、视频预览和成片中排版一致。
2. 白字黑描边、彩字阴影、无背景、半透明底色、背景图片五类样式均可保存和重开。
3. 无背景导出的 PNG 画布空白区域 Alpha 为 0；反锯齿边缘允许中间 Alpha 值；棋盘格不进入文件。
4. 同一 PNG 放在深浅视频帧上不产生意外矩形底板；用户主动设置的背景仍保留。
5. 仅有导入 PNG 时，界面明确提供图片操作；没有“修改文字”假入口，也不自动 OCR 重建后冒充原源文件。
6. 贴片 V2 不改变引用 V1 的历史工程；主动换版后可撤销，预览与导出采用同一图片资产。

## 6. 连接与能力边界

| 能力 | 未连接公司服务 | 已连接公司服务 | 平台前提 |
| --- | --- | --- | --- |
| 本地文案、版本、贴片与工程 | 可用 | 可用 | 已安装并启用插件，有可写存储 |
| 外部 AI 复制 / 粘贴 | 可用 | 可用 | 外部服务自行管理 |
| 个人模型对话 | 有个人配置且服务可达时可用 | 仍可自主选择 | 支持的模型适配器及可用凭据 |
| 公司模型对话 | 不可用或等待重连 | 公司实际提供时可用 | 独立鉴权与能力声明 |
| 公司素材检索 / 新下载 | 不可用，已缓存内容仍可用 | 可用 | 服务接口、权限及资源实际存在 |
| 公司配音 / 字幕 / 视频生成 | 不新建任务，可查看本地已有结果 | 按服务已提供能力开放 | 返回任务身份与可查询状态 |
| 本地素材导入、剪辑 | 已获授权且格式支持时可用 | 同左 | 当前设备文件及媒体能力 |
| 本地 1080p 导出 | 设备与素材通过能力检查后可用 | 同左 | 独立于公司连接，须实测 |
| 团队同步与发布 | 保留待提交内容 | 可提交 | 访问 / 发布权限与版本检查 |

“个人 API 随处使用”仍需要能访问该模型服务的网络；不等于手机离线运行大模型。“连接局域网”也不自动赋予全部服务能力。

公司资源 API 与 DSHA 将自身 Web 工作台开放给局域网的代理是两个概念。插件接公司服务器不要求开放手机代理，不修改宿主端口策略，也不自动让其他电脑访问手机数据。

在电脑浏览器中打开一个由远程主机提供的工作台时，浏览器设备、DSH 宿主和公司服务器可能是三台设备。文件选择发生在哪一端、素材落在哪一端、导出在哪一端执行必须如实展示；不能把服务器输出称为“电脑本地渲染”，也不能把访问手机工作台误称为电脑独立运行。

## 7. 工程、版本与任务的产品契约

### 7.1 必要对象

| 对象 | 必须保持的信息 |
| --- | --- |
| 文案 | 稳定身份、分类、个人 / 团队归属、标题、版本列表 |
| 文案版本 | 正文、分句 / 分镜关系、贴片版本、可选 BGM、作者和来源 |
| 贴片版本 | 可编辑源或“无源”状态、PNG 身份、画布与透明度信息 |
| 素材 | 稳定身份、版本 / 内容摘要、来源、时长、媒体能力、下载状态和可访问位置 |
| 工程及修订 | 文案版本、项目时间基准、输出画布、轨道、片段与素材引用、变换、音量、剪裁范围 |
| 示例关联 | 文案版本与确定示例工程版本，不通过文件名猜配对 |
| 任务 | 稳定身份、目标对象与修订、请求参数、进度、结果、错误和取消状态 |

宿主工作区、可选会话身份与以上对象关联，但当前会话不是插件全局数据的替代品。切换会话不把“最近文案”偷偷绑定到当前工程。

### 7.2 时间与修订规则

项目时间基准贯穿镜头、贴片、字幕和声音。画面剪裁使用明确的帧边界，边界是否包含的规则由技术方案统一，界面预览与导出必须一致。音频按同一时间轴对齐，不强行将音频采样误当视频帧。

AI 调整、素材替换和团队更新均形成可审查的变化；用户手工确认过的剪裁不能因重新检索而无声消失。首次版本只需可靠的撤销 / 重做和工程修订，不引入复杂分支合并界面。

### 7.3 任务与文件状态

任务至少区分排队、运行中、成功、失败、已取消和结果未知。用户关闭页面不等于取消；取消请求已发送不等于远端已经取消。任务重连先查询原身份，支持幂等的服务才可按同一请求恢复。

退出或后台受系统限制时，保留工程及任务记录；恢复后告知真实状态。不承诺所有 Android 系统上息屏持续编码，也不把未知导出自动重新跑一遍。输出先作为未完成结果管理，完成验证后才显示可使用文件。

## 8. DeepSeek Harness 插件接入约束

以下是必须遵循的宿主边界，不代替后续技术规格。当前本地集成基线为 DSH **0.2.1-rc.2**、`dsh-web-mobile` **3.2.1**；上游最新文档仅用于核对设计方向，不能把新 API 直接当成该基线已有接口。

### 8.1 正式插件交付

- 使用 DSH / Cordis 的插件、服务和生命周期方式交付，遵循本仓库[插件包契约](../plugins.md)。合法包名和版本、`dsh.bundle.patch` 及实际存在的补丁文件是安装合同的一部分。
- 有 Web 界面的包按目标运行时要求声明 `dsh.client` 并导出客户端构建产物；服务依赖显式声明，浏览器代码不直接依赖 Node 文件系统或手机私有路径。
- `main` 或 `cordis.entry` 如有声明必须存在；不能误写成所有组合包都强制要求两者。
- 通过宿主正常安装、启用、停用和更新流程管理插件；不修改受管 DSH 核心文件来硬塞业务入口，也不在普通聊天里植入全局 DOM 按钮。
- 升级明确兼容的 DSH 版本与数据版本；安装成功、服务加载成功、UI 可用和媒体操作成功分别验证。未验证的上游版本不宣称兼容。

### 8.2 侧栏、主面板与返回

已核对当前本地运行时：`sidebar.panellist` 是 root 范围的 list 插槽，`main` 是主面板 keyed 插槽，`layout.selectPanel()` 会检查面板已注册。因此插件需注册自身侧栏项与主面板，安装任何插件都自动出现在侧栏的说法不成立。

插件内部的文案列表、详情、工程和编辑器共用一个导航状态。当前移动插件已经处理抽屉、面板退出和返回，但其部分子页判断针对既有插件。新插件必须显式接入可用返回机制；若基线没有通用子路由返回扩展点，则需提出最小宿主适配方案并做兼容验证，不能靠模仿其他插件类名解决。

状态保存在业务服务与持久存储，UI 卸载只释放视图资源。停用时撤销自身注册、监听和预览资源，清楚处理正在运行的任务，不误停其他插件或宿主服务。

### 8.3 业务能力与媒体能力

文案、素材、工程、版本和任务由共用业务层管理；UI 和模型工具均调用这些能力。AI 工具通过目标版本的官方工具体系注册，遵循其权限和执行结果合同，不绕过宿主检查。

媒体适配层负责文件授权、解码、预览和导出。Android 上可能需要宿主提供受控原生媒体能力；桌面由实际支持的宿主或浏览器能力实现。**本次核查没有证明 DSHA 已具备可直接复用的完整多轨剪辑与硬件导出接口**，其实现路线必须先做可行性验证，不能仅因它是客户端就承诺硬件编码已经可用。

同一插件不要求相同的底层二进制。Android 容器的 Linux arm64/glibc、Android 原生能力与桌面系统不是同一运行目标；不能把桌面可执行文件或原生模块直接复制进手机并视为兼容。

### 8.4 权限与数据

使用宿主已有的凭据存储和授权边界，普通文案与剪辑不要求 Root、ADB 或 Shizuku。文件操作限定于用户选择 / 授权的输入和插件自有数据；媒体缓存清理不删除原素材。

公司访问令牌与个人模型密钥不进入工程、分享包、普通日志和提示词。公司服务需验证访问及发布权限；选择个人模型时，应明确本次会发送的公司文案或素材信息，遵循团队配置的外发规则，不能悄悄更换提供方。

以[现有安全模型](../security-model.md)为边界：proot 及插件不是独立安全沙箱；不假定现有局域网 HTTP 代理提供加密传输。生产连接与服务权限在部署方案中落实，本文不新增一套账号、会员或支付平台。

## 9. 响应式与质量要求

### 9.1 界面与交互

- 布局验收覆盖 320、360、390 CSS 像素窄屏、平板及常见桌面窗口；不以设备品牌决定布局。
- 主页面不得横向溢出；时间轴自身可以横向滚动。触摸关键按钮建议至少 44 × 44 CSS 像素，并在正式真机上核对可点击区域。
- 窄屏优先给正文、视频预览和时间轴空间，素材与属性按需展开；桌面可并列显示，不添加不同的一套业务步骤。
- 软键盘、安全区、短屏及 1.3 倍字体下，保存、返回、播放和逐帧按钮仍可到达；不依赖悬停才能使用关键动作。
- 桌面支持键盘焦点和适当快捷键，输入文字时不误触发剪辑快捷键；适配宿主主题及语言机制。
- 无装饰性指标、标语、默认新手长说明。错误给出具体原因与可执行动作，必要帮助按需打开。

### 9.2 性能目标与验收口径

产品范围先控制在一分钟以内、最高 1080p。这能减少工作量与资源需求，但并不等于所有手机都能实时预览或稳定导出。

技术可行性阶段必须在选定的真实设备和桌面环境记录：首次打开工程时间、逐帧响应、连续播放掉帧与音画同步、导出耗时、峰值内存、临时存储峰值、温度 / 后台中断现象。阈值与支持矩阵在实测后进入技术规格，不在本 PRD 中编造“几秒导出”或最低 RAM 保证。

可采用缩略图、波形、下一镜头预加载及预览代理减轻负担；代理预览必须明确与原素材的关系，最终导出采用用户选择的真实质量。全片逐帧解码后全部常驻内存不作为默认路径。

逐帧功能的硬性正确性指标是：确定工程帧位置后，预览与导出对应画面一致；剪裁不退化为关键帧级近似。音画同步、连续播放流畅度另行测量，不能由帧按钮存在推导。

### 9.3 UX、DX、AX 的共同约束

| 决定 | 用户体验 UX | 开发体验 DX | 智能体体验 AX |
| --- | --- | --- | --- |
| 侧栏单入口与对象直达 | 入口稳定，可直接继续工作 | 统一导航和状态来源 | 依据对象身份打开，避免猜当前页面 |
| 明确版本和工程修订 | 旧作品不被新文案改坏 | 数据变更可追踪、可回滚 | 调用指定版本，结果可核对 |
| 贴片源与 PNG 并存 | 能再改文字，也能看到准确效果 | 编辑与合成职责明确 | 可修改样式参数，取得确定的资产结果 |
| 一个业务层、多端能力适配 | 两端使用习惯一致 | 共用规则，隔离平台差异 | 工具调用同一规则，显式获知能力限制 |
| 任务身份与真实状态 | 不重复扣费、不丢结果 | 可重连、可诊断 | 可查询、可取消，不靠重复提交猜成功 |

“不能弄坏任何东西”落实为保护现有聊天草稿、插件启停、宿主返回、用户项目数据和媒体原件，并建立对应回归；它不是在没有验证时声称零风险。

## 10. 空状态、异常与替代路径

| 情形 | 预期行为 |
| --- | --- |
| 初次没有文案 / 工程 | 文案页提供新建 / 导入；工程页提供新建 / 导入素材，不堆说明文字 |
| 文案没有示例 | 不显示可点击的“打开完整示例工程”；维护入口允许关联现有工程 |
| 没有 API Key | 本地与复制流程可用；点击 AI 修改时再提供配置入口 |
| 局域网中断 | 保留已下载素材、选中候选和任务身份；本地编辑继续 |
| 服务生成超时、结果未知 | 查询原任务，不自动重建收费任务或宣称失败已退款 |
| 配音过长或检索无结果 | 定位对应句子 / 镜头，允许调整文案、换候选或自主导入 |
| 素材缺失 / 文件权限丢失 | 定位并重新链接；保留工程剪裁和其他轨道 |
| 字体缺失 | 已有 PNG 照常显示，编辑时选择替代字体并确认新排版 |
| 导入格式不支持 | 在处理前说明；如有已实现的转码服务则提供选择，不伪造缩略图成功 |
| 手机空间不足 | 显示所需空间估算，停止新下载 / 导出；只允许定向清理可重建缓存 |
| 导出中锁屏 / 应用重建 | 保存真实任务状态；恢复后核验结果，保留工程，不保证所有系统后台续跑 |
| 团队版本冲突 | 保存本地内容与服务器版本，允许另存 / 显式更新，不静默覆盖 |
| 用户先剪辑后补文案 | 允许后续关联具体文案版本，不重置已有时间轴 |
| 插件停用或升级 | 正常移除运行注册，保留数据；不丢项目，不触发旧任务重放 |

## 12. 本期不做与待确定项

### 12.1 本期不做

- 付费会员、订阅、积分及订单系统。
- 手机本地运行大模型或手机承担公司视频库向量化。
- 完整复刻剪映的全部特效、复杂动画、无限轨道、专业调色和高级混音。
- 实时多人同时编辑一条时间轴、复杂文案分支合并。
- 插件内部另造独立的插件市场、通用 Agent 框架或账号平台。
- 把 AI 视频生成引擎、音色训练和服务器索引基础设施纳入插件本体重建。

服务器已经提供的音视频生成能力可作为可选任务接入；没有对应服务时不画成已可用按钮。单镜头专注编辑可在主时间轴稳定后增加，同样沿用连续预览和逐帧命令，不另造一套工程格式。

### 12.2 技术规格前需要收敛的事项

| 事项 | 当前处理 | 影响 |
