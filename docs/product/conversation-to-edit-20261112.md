# 对话式文案到剪辑：交互修订

2026-11-12。依据用户本轮要求修订产品流程。本文是目标交互与实施验收依据，不表示现有 APK 或服务已经实现自动编排。代码核对基线：BK `c68bf933`、素材库 `efcc6c2`；既有手机播放和原声修复继续保留。

## 产品决定

用户通过一个创作对话框完成文案讨论、修改、确认及生成。文案库和剪辑器提供直接入口；素材库网页供管理与检查，不作为每次创作的必经页面。

在默认视频创作工作区，用户明确接受当前文案后，系统保存该版本，按已有偏好自动生成可编辑工程。无需再次询问是否搜索、是否下载、是否创建工程。用户说“先保存”“只改文案”“暂时不做视频”时只执行相应请求；正在讨论某个句子或泛泛的“好”不能错误地批准整篇。已有文案点击“生成视频”即表达相同意图，按钮提交引用并立即执行，不要求再点击发送。

“复制选片信息 → 切换页面 → 粘贴 → 输入素材库口令”降为高级导入/排障路径。主流程不展示计划编号、版本、摘要、操作码、跨域配置或接口令牌，不让用户负责跨系统传递它们。系统仍在后台校验来源、权限和版本。

## 用户路径

1. 用户提供文案，或在对话里与 AI 写好文案。文案草稿持续保存；明确接受时创建确定版本。
2. AI 解析当前请求并读取已保存偏好。信息齐全就开始；确实缺少会影响结果的信息，集中问一个简短问题。回答只改变本次任务，只有用户要求记住时才改变长期偏好。
3. 对话显示真实进度，例如“查找画面”“准备配音和音乐”“生成时间线”，提供停止和继续。不会要求用户打开素材库完成中间步骤。
4. 生成完成后，在对话中给出工程卡片与“打开剪辑”。卡片显示预览、时长和需要注意的缺口；直接进入对应工程。已有文案入口发起时，留在原页面并显示同一任务状态，完成后可直接打开。
5. 用户可以自由编辑文字贴片、主视频、配音、背景音乐，也可以继续说“第三个镜头换成近景”“音乐轻一点”。已经手动编辑的工程不得被重试或后续生成静默覆盖。

示例：

> 用户：第二版可以了。
>
> AI：已保存第二版，按你常用的声音和探店风格准备视频。
>
> 状态：已找到 7 段画面，正在生成时间线。
>
> 结果：草稿已生成 · 打开剪辑。

这些结果只在工具返回相应证据后显示。没有配音适配器、连接失败或缺少原片时，不得用静音、提示音、错误素材或空工程冒充成功。

## 文案与偏好

文案保存原文、修订、来源对话和关联工程；首次确认自动归到已有合适分类，不打断创作。无法确定时归入“未分类”，允许后续修改；不擅自创建大量分类、不移动既有手动分类。界面保留版本选择和修改后重新生成入口。

偏好解析顺序：本次明确要求 → 当前文案/工程设置 → 用户已保存默认值 → 产品默认值。解析结果作为本次任务快照保存，任务中途修改全局偏好不改变已执行部分。

| 项目 | 默认行为 | 何时询问 |
|---|---|---|
| 文案版本 | 使用当前已确认版本；库内按钮绑定被点击的版本 | “用刚才那版”同时可能指向多版时 |
| 素材范围 | 使用已连接、已授权的默认素材库 | 没有可用来源，或用户要求范围无法确定时 |
| 配音 | 使用已配置且可用的声音、语速或当前文案音频 | 需要旁白但没有可用配置时，合并询问声音或是否不用旁白 |
| 背景音乐 | 从用户已登记音乐中按默认风格选用，遵循“不加音乐”偏好 | 用户要求音乐但没有可用曲目时；允许已设置的无音乐模式 |
| 文字贴片 | 使用已有模板和风格，保存为可编辑文字/布局 | 只有用户明确要求特殊样式且缺少必要内容时 |
| 原声 | 遵循用户/工程的原声策略，不因生成配音隐式抹掉既有选择 | 用户的原声与旁白要求发生实际冲突时 |
| 时长/画幅 | 使用当前要求或已保存默认值；有旁白时按真实音频安排镜头 | 语音与硬性时长无法同时满足，或请求超出当前能力时 |

不询问已经有明确答案的设置。默认值不能等同于虚构已接入的服务。已配置且在原授权范围内的生成不重复确认；用户明确的新增外部付费选择按既定预算处理，超出原范围才合并询问。

## Skill 与执行服务的分工

视频创作工作区默认加载文案到剪辑的行为说明，用户无需安装或手动调用 Skill。Skill 负责理解意图、判断文案是否确认、解释结果和必要提问；真正的执行由结构化工具和持久任务服务完成，不能靠提示词保证保存、恢复或跨端一致性。

以下为待实现能力边界，不是已经注册的工具名：

- 文案操作：读取、创建、修改、确认版本、归类并引用已有文案。
- 创建草稿任务：根据确认版本和偏好快照创建一个稳定任务，返回任务身份与真实状态。
- 素材操作：查询现有索引、取得候选和选中原片；新增素材需要处理时只提交缺失部分并接回原任务。
- 配音/音乐/贴片：调用实际已配置的提供方，核对产物并登记为工程媒体。
- 任务操作：查询、停止、继续，最终返回可打开的工程引用和未解决项。
- 后续剪辑：解析用户引用的镜头/轨道，调用既有有版本的编辑命令；模糊目标只问目标，不重走全流程。

对话卡片、文案库“生成视频”和后续“继续”调用同一执行入口。模型不自行拼接命令运行服务，不自行选择地址或凭据，也不要求用户复制内部 JSON。

## 后台执行顺序

1. 固定确认文案、配置、目标工作区与单次创作意图，保存任务后执行。重复提交/响应丢失先查询同一任务，不重复合成、下载或创建工程；“再做一版”才创建新意图。
2. 查询已经建立的素材索引；没有依据不能声称全库无素材。入库、镜头切分、画面理解与本次检索分开，不在每次创作时全量重做。
3. 有旁白时先生成或读取真实音频，得到实际时长和句子时间依据，再确定逐句时长和源帧范围；不截断语音或用任意平均分配掩盖不同步。当前缺少语音对齐能力，需要单独实现和验证。
4. 选片与音频准备可在条件满足时并行，最终按真实音频调整。发现品类不符、无镜头或时长不足，优先在授权范围内换候选；仍不足就在对话中集中给出选择，或按既定策略保留明确缺口，不能冒充完整成片。
5. 目标执行端登记媒体，生成可编辑贴片、视频、配音和音乐轨；复用既有准备、提交、回执校验。结果绑定确认的文案版本，不替换成后来未确认的修改。
6. 成功卡片指向确定的工程及工作区。手机本地执行和远程桌面执行必须区分，不能因手机打开网页就声称使用了手机编码。手机离开前台造成原生任务暂停/取消时如实反馈并保留恢复信息，不能假设后台仍在运行。

连接由管理员部署或首次配对配置，凭据留在受控宿主连接层，不进入文案、模型上下文、对话记录、工程或通用浏览器存储。已有连接下零口令输入；连接失效用一个可恢复的状态说明和连接设置入口解决，不丢文案、不重建整个任务。

## 当前代码与缺口

| 已有基础 | 尚需补齐 |
|---|---|
| 文案版本、分类、工程保存与编辑命令 | 对话内写入/确认文案工具，自动分类规则及引用卡片 |
| `copy_edit_describe` 只读 AI 工具 | 生成、查询、继续及后续编辑的 AI 执行工具 |
| 素材库搜索、逐句计划及授权导出 API | BK 宿主连接配置和自动调用这些 API 的编排服务 |
| 浏览器 `selection-import.mjs` 与原子草案合同 | 无手工交接的持久任务，桌面/手机执行适配及对话进度 |
| 配音设置保存、手动音频导入 | 真正的 TTS 适配、声音验证、音频与句子对齐、默认音乐选择 |
| 已有桌面和手机剪辑/播放能力 | 本流程的桌面端到端验收及手机实测，不能用旧导入测试代替 |

现有逐句计划 API 的单次目标不超过 900 帧/30 秒。手机普通剪辑后来放宽了时长，不代表选片接口同步放宽。超出限制应在产品中明确处理，不静默裁掉文案；本修订不凭文档扩大运行能力。

## 实施与验收顺序

先完成同一条竖向流程：已确认文案 + 已连接素材库 + 已保存可用音频/音乐 → 对话发起 → 持久任务 → 自动选片 → 创建工程 → 对话打开。随后接入实际 TTS 与时间对齐，再分别验桌面和手机；文案库按钮与默认 Skill 使用同一入口。

验收必须包含：

1. 已配置用户确认文案后不粘贴信息、不输入令牌、不切素材库页面、不重复确认，直接获得正确工程。
2. 从文案库点击一次“生成视频”不需要再点发送；使用的是点选版本，旧文案不被重写。
3. 无默认声音时只问必要问题；已有默认声音时不问。用户“先保存”不会启动视频任务。
4. 文案确认后新修改不替换正在生成的版本；重复消息、刷新、断线不会重复创建工程或重复调用付费合成。
5. 配音和视频时间相符；贴片、主视频、配音、BGM 可以继续编辑、保存重开。没有要求的音轨允许为空，但不得宣称已生成该音轨。
6. 无素材、品类冲突、服务离线、凭据失效、容量不足和手机进入后台都给出真实可恢复状态，不生成虚假成功卡片。
7. 新一轮生成不覆盖用户已手动剪辑的工程；按明确指令对当前工程修改时使用当前修订及可撤销命令。
