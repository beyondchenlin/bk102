## 发现与修复

替换旧实现把 `outFrame` 原样用于新素材，同时把入点置零。实际页面将 30 fps 的 `[24,105)`（81 输出帧，2.7 秒）替换成 25 fps 后得到 `[0,105)`（126 输出帧，4.2 秒）。这既混用了帧率，又丢失了裁切入点对时长的影响。

现在先计算原镜头的输出帧预算，再按新源 PTS 二分选出不超过该时长的最大合法出点。上述案例在真实页面复验为 `[0,67)`，仍输出 81 帧。新素材过短时缩短；若单个源帧已经长于原镜头，明确报错并保留原工程。不同帧率/VFR 未必能完全命中原时长，取合法边界，不承诺任意素材都能毫秒等长。

修改限定于插件 `src/project.mjs`、关联测试和版本/锁文件。首页、客户端、拖拽、预览播放器及 FFmpeg 管线的实现未改，安装后的文件与本地打包文件相符。没有数据库迁移，旧工程只在用户发起后续编辑时按新规则处理。

## 仍存在的体验边界

1. 当前是先生成 360×640 代理再连续播放。两次首次代理出现约 3.34/3.24 秒，实际开始播放约 4.35/4.25 秒；大桌面观看代理会比 1080P 成片模糊。连续播放流畅不等于实时编辑预览。
2. 素材库为全局共享库，旧色块验收素材仍展示在前面；当前没有项目筛选和清理 UI。为保全既有数据，本轮没有删除它们。
3. 源视频原声目前不会自动带入工程，音频需单独导入并选择；本轮静音素材不能验证真实人声/BGM 混音。字幕及额外叠加轨仍是预留位置。
4. 下载默认文件名仍为 `copy-edit.mp4`，本轮另存为可识别文件名。可在后续改善命名，但本轮未扩大实现范围。
