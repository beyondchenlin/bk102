# 文案与剪辑分类

2026-11-08，桌面插件 `dsh-copy-edit@0.2.0-desktop.25`。

## 使用规则

首页继续上方文案、下方剪辑。各区域标题旁增加分类筛选，与各自的卡片／列表切换独立，搜索条件与分类条件同时生效。

- 初始分类：产品介绍、知识分享、生活记录、情绪表达、活动推广。两个区域各有自己的分类表，可独立修改预置项。
- “全部”“未分类”为固定筛选，不可改名或删除。已有内容均保留在未分类，不推测其业务类型。
- “管理分类”支持新建、重命名、删除；每个区域最多 40 个分类，名称 1–24 个字符，同区域禁止重名及使用固定筛选名称。
- 作品卡片或列表行的 `⋯ → 设置分类` 分配分类。每个作品在每个区域各有一个分类，可将同一工程的文案归为“产品介绍”、剪辑归为“活动推广”。本轮不是多标签或层级目录。
- 在具体分类下新建，自动归入当前区域的该分类；在全部／未分类下新建保持未分类。另一类内容不自动跟随归类。
- 重命名保留归属；删除分类只让该区域的内容回到未分类，不删除文案、工程、素材或媒体结果。

桌面分类与操作同排，空间不足时换行；分类过多可横向滚动。窄屏仍保留两个区域，管理窗口在视口内滚动。无 Android 原生改动。

## 存储与插件边界

`src/categories.mjs` 管理独立的文案库元数据：`library.revision`、`categories.copy/edit`、`assignments.copy/edit`。归属引用稳定 projectId 和 categoryId，名称不作为关联键。

沿用 DSH 的 Cordis 插件、侧栏面板和经过宿主认证的 Typert Remote：新增 `copyEdit/library`，未增加独立服务端口或 DSHA 宿主能力。创建工程可选携带 category，工程与归类在同一个 ProjectStore 写入事务内提交；失效分类不会遗留半成品。

库修改使用 expectedRevision、operationId、既有串行写入和原子文件替换。重复请求在既有有界窗口内返回原结果；旧修订冲突拒绝并提示刷新。没有跨客户端实时推送；重新进入或刷新分类可加载新状态。

旧库缺少 library 时仅在读取结果中提供预置分类，读取不改写磁盘。首次分类写入才持久化；用户清空分类后重开不会重新插入预置项。分类和归属保存到插件数据，而筛选与卡片／列表偏好保存在当前浏览器。

分类不进入工程 revision、剪辑撤销栈或媒体计划。归类不会修改文案版本、素材范围、配音、BGM、贴片绑定，也不会使已有预览／导出缓存失效。现有 `desktop-media.mjs`、`project.mjs`、`timeline.mjs`、连续播放器、裁切、镜头排序、贴片手势和四区域布局文件保持本轮开始时的摘要。
