## 第二轮：真实 DSH 与浏览器复查

复用现有 DSH runtime 和依赖，创建本轮专用空白 DSH_HOME，在动态回环端口启动真实 DSH Web。测试插件 `dsh-hmr-review-only` 遵循 DSH 服务端/客户端入口规范，记录真实 `apply` / `dispose`，没有导入用户账号、素材或项目。测试只修改它自己的客户端文件，触发 DSH 现有文件监听、SSE、客户端模块替换全链路，不通过伪造更新消息充当成功。

| 场景 | 观察结果 |
|---|---|
| 三页同时打开、v1→v2 热更新 | 三页均 `dispose:v1` 后 `apply:v2`，活动实例为 1；一个持有锁、两个等待者 |
| 冻结连接持有页 | 其他页面取得锁；v3 在其余页更新，原页恢复后取得 v3 |
| 刷新后再次更新 | 刷新页直接挂载当前 v3，随后三页都运行 v4，没有重复实例 |
| 真实切换至后台 | 原生 `document.visibilityState` 确认为 `hidden`；该页保留 v4，前台页收到并运行 v5 |
| 切回前台 | 原后台页自动卸载 v4、启用 v5，实例仍为 1 |
| 原生刷新 | 刷新后只有 `apply:v5`，锁数量正常 |
| 关闭连接持有页 | 存活页接手；接下来的 v6 热更新正常完成 |
| 关闭后重开一个页面 | 新页面直接运行 v6，继续共享连接 |
| 全部测试页关闭再重开 | 没有旧等待锁；新页持有唯一锁，随后 v6→v7 热更新成功 |
| 最终连接核验 | 重开页仅一个活跃 `/plugins/events` EventSource，readyState=OPEN |

Ego 默认诊断行为会让后台页仍报告 visible，因此最初的切换观察**不计作真实显隐验收**。额外用浏览器原生 CDP 关闭测试页的焦点模拟、实际切换标签，观察到 hidden→visible 及版本恢复，再还原测试设置。没有向页面伪造 visibilitychange 事件。对应工具返回值摘要在 `native-tab-observations.json`；其他浏览器原始结果在 `browser-hot-initial.json`、`browser-freeze-refresh.json`、`browser-close-reopen.json`。

测试夹具首次启动因漏写 `exports["./client"]` 被 DSH 明确拒绝，失败日志保留；补正夹具后重启成功。这是验证夹具错误，未修改产品来绕过规范。CUA 期间也出现过工具绑定及只读 DOM 能力差异；按工具文档更正后取得原生状态。原生刷新后一次 CDP 读取正遇到工具处理 document response，观察 DOM 恢复后再只读核对成功；不把这一工具等待算作产品断线，也不宣称全程零工具错误。
