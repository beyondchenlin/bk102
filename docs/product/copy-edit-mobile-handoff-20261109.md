## 当前基线与最新决定

- 插件 plugins/dsh-copy-edit，版本 0.2.0-desktop.35；遵循 DSH 0.2.1-rc.2 标准服务端/客户端入口、侧栏与主面板注册、启停卸载契约。同一插件、同一工程模型、平台能力适配，不另起独立产品。
- 宿主当前工作区是 BK102 分支，保留现有品牌、包名、签名和工作区修改，不以历史DSHA发布说明覆盖当前源码身份。
- 唯一入口是宿主侧栏“文案剪辑”；不在每个聊天加常驻业务按钮。
- 首页已改为上方文案、下方剪辑两个自适应内容区域，各自独立卡片/列表、分类、自建分类、搜索、多选批量分类。不要退回旧PRD的两个小入口卡片。
- 文案当前采用用户批准的 B 方案：文案主体突出，配音与BGM在下方，右侧统一工程/贴片预览。手机应重排相同内容，不机械等比缩小。旧PRD“默认无视频预览”已由后续B方案调整，但仍不自动播放或批量下载视频。
- 文案保存明确版本，复制正文高频且优先；草稿与已保存版本分开。完整工程入口必须进入可编辑时间轴，不以MP4代替工程；示例复用保护原件。
- 桌面已具备逐帧、两端拖拽裁切、分割、删除中间片段、镜头拖拽调序、撤销/重做。视频不再受配音时长限制，配音与BGM独立。文字贴片绑定镜头后跟随移动、裁切和分割，仍能手动调整时间。
- 多文字贴片（当前上限30）是多行RGBA PNG与可编辑源，位置、宽度、样式、区间各自保存。不要当成单行字幕或纯CSS文字。
- 桌面四区可拖拽调尺寸、空格播放的输入焦点保护、文案列表宽度调整、分类、版本、预览和1080P导出都要保留。
- 不显示没有实现的字幕/叠加空轨道；不能把占位控件标为支持。
- AI配音公司服务/自有API、音色和参考音频入口及配置已有，但尚无可用TTS实际适配器。不得把配置保存当生成完成。
- 16:9目前只是预览画幅；实际桌面导出仍为1080×1920。实施时明确显示能力，不能把预览选项误称支持横屏导出。

## M0：先修字体与控件尺度

用相同浏览器、视口和100%页面缩放实测宿主与插件 computed font-family/font-size/font-weight/line-height、按钮高度。统一导航、按钮、标签、表单、元信息的层级，复用宿主可用token；必要插件token局部限定，不能全局覆盖宿主或改变浏览器缩放。

特别检查 src/client.css 的超宽容器规则及 src/copy-layout.css 的重复覆盖。目前部分标题、按钮、字段按独立字号设置，需据实测收敛，不先假定14px适合所有位置。文案正文保留适合阅读的字号，贴片画面内文字属于作品数据，不能跟UI缩字号一起改。手机触控范围保持可用（主要操作约44 CSS px），不能把点击范围同步缩小。保留B布局及桌面四区调整。

## M1：手机网页交互完整化

复用现有业务命令与版本模型，不分叉复制桌面编辑器逻辑。

1. 首页两区、卡片/列表、分类及批量操作适合窄屏；不横向溢出、不靠hover操作。
2. 文案列表进入详情、返回原位置；正文编辑/复制/版本保存/历史版本、完整工程入口可用。配音与BGM、统一预览按手机宽高重排；默认9:16，16:9能力如实呈现。文件选择、音乐上传、参考音频入口与服务失败状态均可操作。
3. 剪辑手机默认预览在上、播放控制、时间轴、按需属性抽屉；素材和属性不永久挤在左右两边。保留桌面四区独立布局。
4. 触摸时间轴滚动/缩放、镜头调序、两端裁切、贴片区间拖动要有明确手势边界；处理 pointer capture、pointercancel、多指及滚动冲突、边缘自动滚动，不能一次手势产生大量撤销项。
5. ±1帧、分割/删除中段、撤销/重做、替换/调序、文字绑定、配音/BGM独立规则与桌面一致。多行贴片位置与大小可触摸编辑。
6. 从当前位置连续预览后续镜头，裁切/替换后统一工程时间，配音不被静默截断，BGM连续。后台恢复不重放业务写请求，不把过期渲染结果应用到新修订。
7. 系统返回、宿主面板退出、弹层关闭与子页返回按层级处理；草稿、所选版本、镜头、播放头及任务身份在导航/旋转/卸载恢复时不串项目、不丢已保存内容。检查 dsh-web-mobile 的真实退出协议，不能靠假DOM类名伪装某个宿主页面。
8. 安全区域、软键盘、横竖屏、长标题、大字体、错误/空状态都要验证。桌面尺寸变窄只是布局验证，不能报告为Android验收。

## M2：手机原生媒体能力及宿主边界

先整理“插件自己完成 / 宿主适配器必须提供 / 公司服务提供”的清单，复用既有 experiments/copy-edit-media 隔离预研。现有实验有固定4秒/60秒样本、RenderSnapshot、MediaTaskGate和缓存/票据退役逻辑，但还不是通用工程桥。

历史证据：
- API30 Goldfish 的Surface批量提交掉帧在不经Media3时也可复现；单帧背压用于该模拟器，不能当作所有真机的通用修复。
- 固定4秒120帧、60秒1800帧和部分PTS用例曾通过；后续会话报告仍有预览帧间隔超限，不能选择性引用早期全绿。
- 软件编码60秒导出约95.8秒、首次预览代理准备约63秒等仅属当时模拟器样本；不是手机性能承诺。
- 无ARM64真机性能验收；跨Activity恢复、通用RenderPlan导入、生产媒体桥尚未完成。deviceVerified=false等能力保持诚实。

继续实现可复用的冻结RenderPlan/资产句柄到媒体任务适配，校验版本、revision、内容摘要、片段PTS、输出配置；预览与导出引用同一工程语义。插件Host负责业务与版本，Android负责文件授权、解码、Surface、编码、后台任务和系统分享，不往HarnessController塞业务剪辑职责。

宿主改动拆分成独立协作者/契约/测试，默认能力检测失败时降级，不影响现有安装、启动、聊天、备份、运行时和桌面连接。不得传入任意shell命令、信任任意页面路径，或把整个视频base64来回经JS桥。任务有身份、代次、取消、资源释放；旧完成回调不能发布新工程结果。输出先临时文件，验证后发布；不得先删上一份成功成片。

先跑严格4秒门禁，再同一构建同一设备测60秒：逐帧入出点、连接帧、连续预览帧间隔、音画同步、独立配音/BGM、多贴片、导出PTS/帧内容/时长、失败及取消。区分首次预处理等待、播放掉帧、模拟器编码慢、Media3/业务问题，不只加超时重试。

用户已有设备授权只覆盖“空闲的现有Android模拟器，独立包dsh.copyedit.spike，自制素材，不改DSHA和用户数据”。可以复用闲置DSHA_API30，先核验没有其他任务占用，不创建新大环境。新手机目标不等于生产设备覆盖授权；需要真机安装/生产宿主实测时再明确申请该具体动作，同时继续不依赖设备的代码与测试。不要把这一边界当作停止全部手机开发的理由。
