# 媒体任务基础与下一步开发

日期：2026-11-08。承接[媒体修复验证](copy-edit-media-fix-report.md)，本轮继续在独立 `dsh.copyedit.spike` 中开发。没有修改 DSH 插件协议、DSHA/BK102 宿主、生产安装包或公司服务器。

## 本轮收敛的能力

1. **冻结渲染请求。** `RenderSnapshot` 绑定工程 ID、修订号、素材 SHA-256、镜头顺序和裁切区间、贴片两行文字、输出配置及渲染管线版本。输入集合做防御性复制；不同修订、不同内容、预览与正式导出不会共享同一个缓存键。固定音量、颜色、描边等实现变化必须递增管线版本。
2. **版本匹配的缓存。** 原来的 `Map<Boolean, File>` 只区分 4/60 秒，已经移除。缓存命中必须同时满足槽位、快照键、文件大小和完整摘要；文件被替换或损坏即失效。当前仍只支持会话内固定样本，不扫描旧目录，也不把跨 Activity 的磁盘残留当作已验证缓存。
3. **可退休的任务票据。** 开始任务时绑定快照。主动取消、工程修订变化、后台或页面销毁先使票据失效，再停止 Transformer。旧完成/错误回调不能发布结果；播放器回调也检查前台状态与播放代次，避免迟到首帧回调重新启动播放。底层停止或清理异常时阻止本会话再开始媒体任务。
4. **保留上一份成功成片。** 输出先写本会话亲自创建的 `job-*.part.mp4`，Media3 完成且报告的帧数满足当前计划后才原子替换最终文件。不支持原子替换则失败，不先删除旧成片。取消只清理本实例登记的临时文件，未知文件、旧证据与用户文件不扫描、不删除。帧内容与 PTS 的最终正确性仍需独立读回，不能只凭 Media3 的计数宣称所有媒体均准确。
5. **验证记录绑定本次运行。** runner 等 Android 启动完成后才安装；安装日志保留。每次仪器化带独立 run ID，旧 JSON 不作为当前证据；60 秒继续要求同一 APK、同一设备的严格 4 秒门禁。

当前示例中的“切换贴片版本”只修改两个固定贴片样式并递增内存修订号，用来验证失效链。**这不是文案版本库，也没有把业务版本管理搬进原生层。** 用户可持久保存的文案、工程版本与团队权限仍由 DSH 插件 Host 负责。

## 验证范围

新增单元场景覆盖不可变快照、缓存身份变化、取消后旧票据不能结束新任务、重复任务拒绝、失败/取消保留旧文件、成功原子替换、文件被改后缓存失效，以及拒绝清理未登记文件。

模拟器场景覆盖：V1 首次生成与命中；生成旧成片后开始 V2 导出、待临时文件实际写入后取消；V2 必须重新生成且贴片 PNG 改变；V3 准备期间退到后台再回来，不自动续播、不复活旧任务；重新点击后新任务可以完成。4/60 秒媒体读回另行记录，以免功能状态测试冒充媒体正确性检查。

| --- | --- |

两次超时均出现在约 3.2 秒附近，而版本/取消场景的四次播放均通过节奏指标。新旧 4 秒预览音频解码后的 PCM 摘要相同；这些事实不足以单独判断是模拟器音频时钟、负载还是实现问题，不把它写成已排除回归。按用户随后提出的桌面优先方向，本轮结束进一步性能试验，保留失败用于后续目标设备调查，没有放宽指标或反复重跑到绿色。

精确制品与源码摘要见 `build/copy-edit-spike/media-session-manifest.json`。旧失败不删除：包括模拟器尚未完成启动时的安装失败，以及把 Android 系统 `/data/user/0` 链接误当作任务目录链接的首次检查失败。后者修正为先解析可信 `Context.getFilesDir()` 根，再对任务子目录与输出文件做检查，未放开任意外部路径。另有一次仪器化逻辑通过但缺少正确 run ID 的中间结果（`065013`），不作为完整回执通过证明。

## 接下来建议的顺序

用户强调需要公允判断。桌面先做是调整业务开发顺序，不代表桌面媒体引擎可以直接在 Android 运行。文案/工程业务与大部分前端共用；手机交互需要按触摸和窄屏设计；本地逐帧、预览和导出仍需 Android 原生适配与 DSHA 宿主接入。完整原则见[桌面优先与移动适配边界](copy-edit-desktop-first-plan.md)。

1. **文案与版本最小闭环。** 在已跑通的 DSH 插件中实现文案编辑、保存 V1/V2、选中版本创建工程快照。共用现有 Host/Client RPC，不新增旁路服务；以自制示例素材先连通业务流程。
2. **明确媒体适配器合同。** 插件发工程快照与素材句柄，适配器返回任务 ID、状态、能力与产物句柄。当前类可复用，但还没有完成生产桥、原生 Surface 承载、文件授权或持久化任务。宿主改动作为单独交付与回归范围。
3. **实体设备验证与等待体验。** 在实际 Android/ARM64 手机验证硬件编解码、4/60 秒导出、温度/内存与直接预览。当前完整缓存首次仍需准备；分镜级缓存、局部失效与预读可在合同固定后优化。
4. **再接实际资源和编辑界面。** 文案索引公司素材、AI 声音、服务器下载与时间轴均建立在上述小闭环上。当前不把模拟器通过等同于完整编辑器或任意多视频轨道已可交付。

## 保留边界

- 4/60 秒、1080P、30 fps、固定主视频序列与两路音频仍是验证范围；通用 B 帧/VFR/60 fps 成片矩阵未完成。
- 当前修订号、任务和缓存索引不跨进程恢复；进程被杀后的孤立临时文件不会自动扫描删除，也没有后台服务、断点续导或批量历史回收。
- 程序仍是前台验证入口，没有将 `deviceVerified` 或插件媒体能力置为 true。
- 正常取消路径已经实际验证；停止/删除失败、磁盘不足等故障注入不在本轮设备验收内。

收尾：本任务模拟器已正常关闭；原有 45 个 tracked 修改文件摘要不变，没有新增 worktree。复用原工具链、隔离运行时与素材。新增成片/证据保留在 `build/copy-edit-spike`；应用内本轮取消产生的临时文件已按登记清理，未知文件未删除。此前审批拒绝的宿主模拟器临时文件未重试清理，本轮模拟器写入层也保留，详见清单；没有宣称释放磁盘空间。
